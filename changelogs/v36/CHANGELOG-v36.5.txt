# v36.5 — Email Experience Upgrade

This release upgrades Service Desk emails from plain operational messages into branded, action-oriented product emails while also hardening SMTP delivery behavior.

## Email design
- Added a reusable branded HTML email renderer aligned to the site theme:
  - clean white canvas
  - mint accent #00C2A8
  - purple accent #7C3AED
  - soft yellow callouts #FFE66D
  - dark text #1F2937
- Added responsive email layout with:
  - branded hero section
  - issue snapshot card
  - status/severity/product/entity metadata
  - strong CTA buttons
  - secondary dashboard link
  - customer-safe footer
- Added graceful plain-text fallback for all generated emails.

## Email types covered
- User provisioning / welcome email
- Forgot password email
- Issue created
- Issue assigned
- Issue status changed
- Issue reopened
- Issue comment added
- SLA response breached
- SLA resolution breached
- Jira push success
- Agent closure required
- Branded test email

## CTAs and deep links
- Emails now use PUBLIC_APP_URL / BASE_URL to build portal links.
- Issue emails deep-link to the relevant issue.
- Notification emails include a secondary dashboard link.
- User provisioning emails include a sign-in CTA.
- Password reset emails include a reset CTA.

## Reliability hardening
- Added SMTP connection timeout, greeting timeout, socket timeout configuration.
- Added optional SMTP pooling configuration.
- Added structured SMTP failure reasons with code/command/response/message where available.
- Notification queue still handles email delivery asynchronously and supports EMAIL_MAX_ATTEMPTS.
- Added admin Notification Center action to send a branded test email to the current user.

## New/updated environment variables
- PUBLIC_APP_URL
- SMTP_CONNECTION_TIMEOUT_MS
- SMTP_GREETING_TIMEOUT_MS
- SMTP_SOCKET_TIMEOUT_MS
- SMTP_POOL
- SMTP_MAX_CONNECTIONS
- SMTP_MAX_MESSAGES
- SMTP_TLS_REJECT_UNAUTHORIZED
- EMAIL_MAX_ATTEMPTS
