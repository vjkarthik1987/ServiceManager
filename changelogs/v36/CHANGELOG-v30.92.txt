v30.92 — Schema-aware assistant issue creation

What changed:
- Chatbot no longer jumps from issue description directly to final confirmation with defaulted schema fields.
- Assistant now asks a schema-aware classification step before creating issues.
- Uses tenant configured severity/priority master list, category master list, and request type options.
- Provides suggestions but asks the user to confirm or override: e.g. BUG, HIGH, Access.
- “yes” during schema selection accepts suggestions; “yes” during final confirmation creates the issue.
- Keeps deterministic guardrails around OpenAI so defaults are not silently treated as user choices.

Why:
- OpenAI-backed flow must behave like an intelligent service-desk assistant, not a dumb extractor/defaulting bot.
