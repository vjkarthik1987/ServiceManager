# Service Desk v20.2 release notes

## Cloud baseline

v20.2 introduces a one-shot, dry-run-first bootstrap for the `suntec` workspace. It is intended for a clean cloud MongoDB baseline and is idempotent.

## Service catalogue

The bootstrap creates four top-level Issue Families:

1. Ticket — Incident, Service Request, Change Request, Query.
2. Incident — Application, Security, Operational, Infrastructure.
3. Maintenance Request — Scheduled Maintenance, Proactive Maintenance, Emergency Maintenance, Vulnerability Run, Penetration Test Run, Actual DR.
4. Service Request — the Xelerate SaaS service-request catalogue configured in the bootstrap.

## Customer models

### Standard Bank

Standard Bank, Standard Bank Retail Banking and Standard Bank Corporate Banking use the Ticket family only. Customer-created Ticket requests enter SunTec Operations directly at L3. Customer users remain reporters/participants but do not receive operational task checklists. Clarification and verification use comments/customer-facing status rather than a customer task stage.

### Danske Bank

Danske Bank, Danske Bank Retail Banking and Danske Bank Corporate Banking use SaaS Incident, Maintenance Request and Service Request families. The bootstrap uses the configured Bank/Partner/SunTec support flows, including critical Application Incident parallel L2 + L3 routing for S1/S2 Production/DR under the default parallel mode.

## UI

- Browser favicon added throughout the application.
- Request list heading is “See requests”.
- A one-click “Requests assigned to me” filter is available above the request table.
- Dashboard adds calendar pulse cards for Today, This Week, This Month, Open Now, Resolved This Month and SLA Attention.
- Dashboard ranking cards show Issue Family, Status, Client and Assigned Workload.
- Help & FAQ includes visual examples of direct-to-L3 normal support and SaaS support.

## Known configuration limits

The bootstrap prints the current static-model limitations during preview/apply, including per-family default SLA limits, dynamic previous-status reversion, timed reminder automation and some transition-level role restrictions.
