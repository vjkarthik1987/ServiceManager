# Service Desk v19.8.2

Foundation and admin-hardening release.

## Organization activation
- New organizations are created in `pending` state.
- The first administrator receives a one-time activation link.
- Activation links are SHA-256 hashed at rest, expire after 24 hours, and can be used once.
- The administrator chooses the initial password during activation.
- The organization becomes `active` only after administrator activation completes.

## Password recovery
- Forgot-password links are available on admin and tenant login pages.
- Admin reset requires tenant + email; tenant reset uses the workspace slug.
- Responses do not disclose whether an email exists.
- Reset links expire after 30 minutes and are one-time use.

## Admin/user access
- A tenant administrator can be created without any client assignment.
- Client assignments remain optional for tenant admins who also need tenant-portal roles.
- User validation errors remain inside the modal.

## Regions and environments
- Region timezones use a searchable/native IANA timezone dropdown populated by the browser.
- Region and Environment library headers have consistent card padding.
- Region/environment codes accept a minimum of 2 characters.
- Short descriptions such as `DR` are accepted.

## Client administration
- Admins can permanently delete a client only when it has no child clients, historical requests, or user assignments.
- Otherwise the UI explains why deletion is blocked and the client can be deactivated instead.

## Form errors
- Expected POST validation/conflict errors (400/409/422) return to the originating page with an inline/global error instead of opening the generic error page.
