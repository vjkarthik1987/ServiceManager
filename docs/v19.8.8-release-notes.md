# Service Desk v19.8.8

## Request workbench

- Jira-style two-pane issue workspace: issue work in the main pane, operational control tower on the right.
- Support journey and workflow progress appear before Description.
- Customer-facing status is separated from internal workflow status.
- SLA moved into the right control tower with unclipped visual Response, Next Update and Resolution trackers.
- Tasks collapsed to a compact summary and a right-side task drawer.
- Status changes, assignment, support routing and task updates use right-side drawers rather than detached centre modals.

## Ownership and assignment

- Active support stages now carry a first-class assignee snapshot.
- Eligible owners are driven by each support stage's configured owner-side: Customer/Bank stages list client users, Partner stages list partner users, and SunTec stages list SunTec agents/managers, all scoped to the request client and configured support level.
- Eligible users can Take ownership of an unassigned stage.
- Tenant Admin and eligible Agent Manager can assign/reassign.
- An Assigned workflow status cannot be entered without a stage owner.
- Existing requests are reconciled against the live support-path configuration in the workbench, so updated Ticket L2 ownership and new return routes do not require recreating the request.

## Routing

- Support movement can originate from any active stage, including a parallel L3 stage.
- Support paths now explicitly support configurable return movements as well as forward and parallel movements.
- Provisioned Ticket paths include L2 → L1, L3 → L2 and L3 → L1 return actions.
- SaaS Application Incident paths include Partner → Bank and SunTec → Partner/Bank return actions.
- Security, Operational and Infrastructure default paths include L3 → L2 return actions; no undocumented L1 stage is invented for those processes.
- Selected Service Request paths also include appropriate return movements.

## Tasks

- Completing or cancelling a task requires a completion note of at least 3 characters on both the request drawer and full task page.
- Backend validation enforces the note requirement even if browser validation is bypassed.

## Queue density

- Request list no longer needs repetitive row-level Open/New action links; the whole row opens the request.
- Denser fixed-layout columns are designed to fit standard laptop widths at 100% zoom.
- Sidebar typography and spacing are slightly smaller.

## Help

Help & FAQ now explains stage ownership, take ownership, manager assignment, return routing, customer status vs internal status, task drawers and mandatory task completion notes.
