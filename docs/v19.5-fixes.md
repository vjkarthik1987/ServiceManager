# v19.5 fixes and UX improvements

## Context-aware request intake

- Fixed the administrator request-intake client search. Filtered client cards now reliably disappear because the shared stylesheet explicitly respects the HTML `hidden` attribute.
- Single-option dropdowns are automatically selected and displayed as fixed values.
- Fixed values are submitted through hidden inputs even though the visible select is disabled.

## User access

- New client assignments no longer default to `Agent user`.
- The assignment builder derives the default access profile from the user’s existing assignments; a client user therefore receives `Client user` when another client is added.
- Client access displays `Client portal` instead of irrelevant L1/L2/L3 controls.
- Partner and agent access retain support-level configuration.

## Client operational rules

- Replaced the compressed operational-rule table with readable responsive cards.
- Request subtype, support path, conditions, inheritance, and status are visually separated.

## SLA journey

- Connector arrows now sit above the milestone border rather than inside or beneath it.
- Responsive mobile arrows continue vertically between milestone cards.

## Workflow tasks

- Rebuilt the request task area as a stage-based task workspace.
- Shows completion progress, open work, completed work, blocking state, source workflow status, queue, latest note, and completion details.
- Blocking tasks are surfaced before status or support movement actions.
- Locked actions scroll directly to the blocking stage.
- Task updates use a focused modal with status and note.
- Task completion actor, completion time, and note are retained.
- Server-side validation now blocks both workflow status changes and support-path movement while blocking tasks remain open.
