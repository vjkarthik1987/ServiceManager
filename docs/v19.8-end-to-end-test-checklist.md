# Service Desk v19.8 — End-to-End Test Checklist

Use the existing MongoDB database. Do not run a reset or demo seed.

## 1. Startup
- Start MongoDB on `127.0.0.1:27017` using the user-profile data directory.
- Start Service Desk and confirm all four processes remain running.
- Open the admin portal and confirm Example Bank, existing workflows, requests, and tasks are present.

## 2. User administration
- Open **Users** and click **Add user** once.
- Confirm the modal opens immediately and the page does not remain behind a global loading spinner.
- Submit without selecting a client.
- Confirm the modal stays open and shows an inline validation message.
- Select Example Bank, create the user, and confirm the save returns quickly even when SMTP is unavailable.
- Reopen **Edit** for the same user twice and confirm the reusable editor opens both times with the correct assignments.
- Confirm the green status dot and `Active` text remain adjacent.

## 3. Workflow Studio
- Search for `Application Incident – L1 Bank`.
- Open it, close it, and open it again.
- Confirm the full-screen editor opens immediately each time and shows an internal loading state while fetching.
- Hover and click transition-matrix cells; confirm the source row and target column headers are highlighted.
- Click a `+` between two statuses and add a temporary status.
- Keep **Connect it between its neighbours** selected and confirm the direct neighbour transition is replaced by previous → new → next.
- Edit or deactivate the temporary status and verify existing historical status IDs are preserved.

## 4. SLA journey
- Open request `EXABAN-01021` or another request with an active SLA.
- Confirm arrows are vertically centred on the boundary between milestone cards rather than floating above the rail.
- Check desktop and narrow-window behaviour.

## 5. Task detail
- Open a generated task such as `EXABAN-01021-T001`.
- Confirm the page clearly separates task purpose, ownership, parent request context, dates, visibility, comments, attachments, activity, and actions.
- Add a comment, update task status, and return to the parent request.

## 6. Existing Application Incident flow
- Open the existing Example Bank S3 Application incident.
- Confirm its Standard support path, active support stage, workflow status, task IDs, and SLA state are intact.
- Complete blocking tasks and progress through an allowed status transition.
- Attempt an invalid transition and confirm a clear in-page error is shown.
- Move from L1 to L2 with a comment of at least three characters.
- Confirm the UI responds immediately and email delivery does not block the request action.

## 7. Regression checks
- Issue Families remain collapsed by default and preserve expansion state after subtype creation.
- New families and subtypes appear at the top.
- Client operational rules, support paths, workflows, task templates, saved filters, comments, attachments, SLA clocks, and audit history remain available.
