# v20.1 release notes

v20.1 focuses on onboarding and identity-email reliability while keeping the v20 request/workflow behaviour unchanged.

## Registration and activation mail

- Organization activation mail is now awaited instead of being fire-and-forget, so the setup screen reports the actual delivery result.
- SMTP mail is retried automatically (default: 2 attempts) with a fresh transporter between attempts.
- A pending organization can resend a fresh one-time activation email without recreating the organization.
- The pending-workspace screen distinguishes SMTP success, SMTP failure, and console mail mode.

## User registration / access mail

- New-user invitation mail is now attempted before the create-user flow reports completion.
- If SMTP fails, the user remains created and the Users page clearly says the invitation failed rather than silently losing the mail.
- Active users now have a **Send access email** action. It issues a fresh one-time password/access link and sends it through the same proven mail transport.

## Mail URL and retry configuration

Optional `.env` settings:

```env
MAIL_RETRY_ATTEMPTS=2
MAIL_RETRY_DELAY_MS=750
PUBLIC_BASE_URL=
```

`PUBLIC_BASE_URL` can be set to the externally reachable Service Desk URL so activation/reset/verification links do not depend on the browser Host header. If blank, the current request host is used.

## Compatibility

No database migration and no service-model provisioning rerun is required for v20.1.
